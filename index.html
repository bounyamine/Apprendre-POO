Apprendre la POO en Java

Un tutoriel interactif pour maîtriser les concepts de la Programmation Orientée Objet

Introduction à la POO

La Programmation Orientée Objet (POO) est un paradigme de programmation qui utilise des "objets" pour modéliser des données et des comportements. Java est un langage entièrement orienté objet.

Les piliers de la POO

  1. Classes et Objets - Les objets sont des instances de classes, qui sont des modèles pour créer des objets.
  2. Encapsulation - Protection des données en limitant l'accès direct aux attributs.
  3. Héritage - Une classe peut hériter des attributs et méthodes d'une autre classe.
  4. Polymorphisme - Un objet peut prendre différentes formes selon le contexte.
  5. Abstraction - Simplification de la réalité en se concentrant sur les aspects essentiels, en masquant les détails complexes.

Contrairement à la programmation procédurale qui se concentre sur les procédures (fonctions), la POO se concentre sur les objets qui contiennent à la fois des données et des méthodes qui opèrent sur ces données.

Avantages de la POO

  • Modularité - le code est divisé en modules indépendants
  • Réutilisabilité - les classes peuvent être réutilisées dans différentes parties du programme
  • Facilité de maintenance - les modifications sont isolées aux classes concernées
  • Sécurité - l'encapsulation protège les données sensibles

Note: La POO n'est pas toujours la meilleure approche pour tous les problèmes. Certains problèmes simples peuvent être résolus plus efficacement avec une approche procédurale.

Classes & Objets

Les classes et les objets sont les concepts fondamentaux de la POO.

Qu'est-ce qu'une classe?

Une classe est un modèle ou un plan qui définit les attributs (données) et les méthodes (comportements) que les objets de cette classe auront.


public class Voiture {
    // Attributs (variables d'instance)
    private String couleur;
    private int vitesse;
    private boolean demarree;
    
    // Constructeur
    public Voiture(String couleur) {
        this.couleur = couleur;
        this.vitesse = 0;
        this.demarree = false;
    }
    
    // Méthodes
    public void demarrer() {
        this.demarree = true;
        System.out.println("La voiture démarre!");
    }
    
    public void accelerer() {
        if (demarree) {
            this.vitesse += 10;
            System.out.println("Vitesse: " + this.vitesse + " km/h");
        } else {
            System.out.println("Vous devez d'abord démarrer la voiture!");
        }
    }
    
    public void freiner() {
        if (this.vitesse > 0) {
            this.vitesse -= 10;
            if (this.vitesse < 0) this.vitesse = 0;
            System.out.println("Vitesse: " + this.vitesse + " km/h");
        }
    }
}

Qu'est-ce qu'un objet?

Un objet est une instance d'une classe. Si la classe est un plan, l'objet est la structure construite selon ce plan.


// Création d'objets de la classe Voiture
Voiture maVoiture = new Voiture("rouge");
Voiture voitureDeSport = new Voiture("bleu");

// Utilisation des objets
maVoiture.demarrer();
maVoiture.accelerer();  // Vitesse: 10 km/h
maVoiture.accelerer();  // Vitesse: 20 km/h

voitureDeSport.accelerer();  // "Vous devez d'abord démarrer la voiture!"
voitureDeSport.demarrer();
voitureDeSport.accelerer();  // Vitesse: 10 km/h

Points clés à retenir

  • Une classe définit le modèle, un objet est une instance concrète de ce modèle
  • Les attributs stockent l'état de l'objet (couleur, vitesse, etc.)
  • Les méthodes définissent le comportement de l'objet (démarrer, accélérer, etc.)
  • Le constructeur est une méthode spéciale appelée lors de la création d'un objet
  • Le mot-clé this fait référence à l'objet actuel

Encapsulation

L'encapsulation est le principe de cacher les détails d'implémentation et de ne fournir qu'une interface contrôlée pour interagir avec l'objet.

Principes de l'encapsulation

  • Rendre les attributs privés (avec le mot-clé private)
  • Fournir des méthodes publiques pour accéder aux attributs (getters et setters)
  • Contrôler l'accès aux données (validation, calculs, formatage)

public class CompteBancaire {
    // Attributs privés
    private String proprietaire;
    private double solde;
    private String numeroCpte;
    
    // Constructeur
    public CompteBancaire(String proprietaire, String numeroCpte, double soldeInitial) {
        this.proprietaire = proprietaire;
        this.numeroCpte = numeroCpte;
        
        // Validation dans le constructeur
        if (soldeInitial < 0) {
            this.solde = 0;
            System.out.println("Solde initial ne peut pas être négatif. Initialisé à 0.");
        } else {
            this.solde = soldeInitial;
        }
    }
    
    // Getters (accesseurs)
    public String getProprietaire() {
        return proprietaire;
    }
    
    public double getSolde() {
        return solde;
    }
    
    public String getNumeroCpte() {
        // Masquer partiellement le numéro pour des raisons de sécurité
        return "XXXX-XXXX-" + numeroCpte.substring(numeroCpte.length() - 4);
    }
    
    // Setters (mutateurs) avec validation
    public void setProprietaire(String proprietaire) {
        if (proprietaire != null && !proprietaire.isEmpty()) {
            this.proprietaire = proprietaire;
        } else {
            System.out.println("Le nom du propriétaire ne peut pas être vide.");
        }
    }
    
    // Pas de setter pour le numéro de compte (immutable)
    
    // Méthodes pour manipuler les données
    public void deposer(double montant) {
        if (montant > 0) {
            this.solde += montant;
            System.out.println("Dépôt de " + montant + "€ effectué.");
            System.out.println("Nouveau solde: " + this.solde + "€");
        } else {
            System.out.println("Le montant du dépôt doit être positif.");
        }
    }
    
    public void retirer(double montant) {
        if (montant > 0) {
            if (this.solde >= montant) {
                this.solde -= montant;
                System.out.println("Retrait de " + montant + "€ effectué.");
                System.out.println("Nouveau solde: " + this.solde + "€");
            } else {
                System.out.println("Solde insuffisant pour ce retrait.");
            }
        } else {
            System.out.println("Le montant du retrait doit être positif.");
        }
    }
}

// Exemple d'utilisation de la classe CompteBancaire
CompteBancaire compte = new CompteBancaire("Jean Dupont", "1234-5678-5678", 1000);

// Accès contrôlé aux données
System.out.println("Propriétaire: " + compte.getProprietaire());
System.out.println("Numéro de compte: " + compte.getNumeroCpte()); // Affiche "XXXX-XXXX-5678"
System.out.println("Solde: " + compte.getSolde() + "€");

// Tentative de modification avec validation
compte.setProprietaire(""); // Erreur: "Le nom du propriétaire ne peut pas être vide."
compte.setProprietaire("Marie Dupont"); // OK

// Opérations sur le compte
compte.deposer(-100); // Erreur: "Le montant du dépôt doit être positif."
compte.deposer(500);  // "Dépôt de 500€ effectué. Nouveau solde: 1500€"
compte.retirer(2000); // Erreur: "Solde insuffisant pour ce retrait."
compte.retirer(300);  // "Retrait de 300€ effectué. Nouveau solde: 1200€"

Avantages de l'encapsulation

  • Protection des données - Empêche les modifications accidentelles ou malveillantes
  • Contrôle de l'accès - Permet de valider les données avant de les modifier
  • Flexibilité - Permet de modifier l'implémentation interne sans affecter le code qui utilise la classe
  • Maintenabilité - Facilite la détection et la correction des erreurs

Bonnes pratiques:

  • Toujours déclarer les attributs en private sauf raison particulière
  • Utiliser des getters/setters pour contrôler l'accès aux données
  • Ajouter de la validation dans les setters pour garantir l'intégrité des données
  • Ne pas créer de setters pour les attributs qui ne doivent pas être modifiés après la création

Héritage

L'héritage est un mécanisme qui permet à une classe d'acquérir les propriétés et comportements d'une autre classe. C'est une relation "est un" entre les classes.

Terminologie

  • Superclasse (classe parent): La classe dont les caractéristiques sont héritées
  • Sous-classe (classe enfant): La classe qui hérite des caractéristiques
  • mot-clé "extends": Utilisé pour établir la relation d'héritage
  • mot-clé "super": Permet d'accéder aux membres de la superclasse

// Classe parent (superclasse)
public class Vehicule {
    protected String marque;
    protected String couleur;
    protected int vitesse;
    
    public Vehicule(String marque, String couleur) {
        this.marque = marque;
        this.couleur = couleur;
        this.vitesse = 0;
    }
    
    public void accelerer() {
        this.vitesse += 5;
        System.out.println("Vitesse actuelle: " + this.vitesse + " km/h");
    }
    
    public void freiner() {
        if (this.vitesse >= 5) {
            this.vitesse -= 5;
        } else {
            this.vitesse = 0;
        }
        System.out.println("Vitesse actuelle: " + this.vitesse + " km/h");
    }
    
    public void klaxonner() {
        System.out.println("Beep beep!");
    }
    
    // Getters et setters
    public String getMarque() { return marque; }
    public String getCouleur() { return couleur; }
    public int getVitesse() { return vitesse; }
}

// Classe enfant (sous-classe)
public class Voiture extends Vehicule {
    private int nombrePortes;
    private boolean climatisation;
    
    public Voiture(String marque, String couleur, int nombrePortes) {
        // Appel du constructeur parent
        super(marque, couleur);
        this.nombrePortes = nombrePortes;
        this.climatisation = false;
    }
    
    // Nouvelle méthode spécifique à la voiture
    public void activerClimatisation() {
        this.climatisation = true;
        System.out.println("Climatisation activée.");
    }
    
    // Redéfinition (override) d'une méthode de la classe parent
    @Override
    public void accelerer() {
        // La voiture accélère plus vite qu'un véhicule standard
        this.vitesse += 10;
        System.out.println("La voiture accélère! Vitesse: " + this.vitesse + " km/h");
    }
    
    // Getters spécifiques
    public int getNombrePortes() { return nombrePortes; }
    public boolean hasClimatisation() { return climatisation; }
}

// Autre classe enfant
public class Moto extends Vehicule {
    private boolean sidecar;
    
    public Moto(String marque, String couleur, boolean sidecar) {
        super(marque, couleur);
        this.sidecar = sidecar;
    }
    
    @Override
    public void klaxonner() {
        System.out.println("Tut tut!");
    }
    
    @Override
    public void accelerer() {
        // La moto accélère encore plus vite
        this.vitesse += 15;
        System.out.println("La moto accélère rapidement! Vitesse: " + this.vitesse + " km/h");
    }
    
    public boolean hasSidecar() { return sidecar; }
}

Points importants sur l'héritage

  • Java ne permet pas l'héritage multiple (une classe ne peut pas hériter de plusieurs classes)
  • Tous les constructeurs d'une classe enfant doivent appeler un constructeur de la classe parent (avec super())
  • Les membres private de la classe parent ne sont pas accessibles directement dans la classe enfant
  • Les membres protected sont accessibles dans la classe enfant
  • Toutes les classes en Java héritent implicitement de la classe Object

Attention: Utilisez l'héritage seulement quand il existe une véritable relation "est un". Pour une relation "possède un", préférez la composition.

Polymorphisme

Le polymorphisme permet aux objets d'adopter différentes formes selon le contexte. En Java, il existe deux types de polymorphisme:

1. Polymorphisme statique (surcharge de méthodes)

La surcharge de méthodes permet de définir plusieurs méthodes avec le même nom mais des paramètres différents.


public class Calculatrice {
    // Surcharge de la méthode additionner
    public int additionner(int a, int b) {
        return a + b;
    }
    
    public double additionner(double a, double b) {
        return a + b;
    }
    
    public int additionner(int a, int b, int c) {
        return a + b + c;
    }
    
    public String additionner(String a, String b) {
        return a + b;  // Concaténation de chaînes
    }
}

Le compilateur détermine quelle méthode appeler en fonction des arguments passés:


Calculatrice calc = new Calculatrice();
System.out.println(calc.additionner(5, 3));           // Appelle la 1ère version: 8
System.out.println(calc.additionner(5.5, 3.2));       // Appelle la 2ème version: 8.7
System.out.println(calc.additionner(5, 3, 2));        // Appelle la 3ème version: 10
System.out.println(calc.additionner("Hello ", "World")); // Appelle la 4ème: Hello World

2. Polymorphisme dynamique (redéfinition de méthodes)

La redéfinition de méthodes permet à une sous-classe de fournir une implémentation spécifique d'une méthode déjà définie dans la classe parent.


// Utilisation du polymorphisme avec les classes précédentes
Vehicule vehicule1 = new Vehicule("Générique", "Gris");
Vehicule vehicule2 = new Voiture("Toyota", "Rouge", 5);  // Upcast implicite
Vehicule vehicule3 = new Moto("Yamaha", "Noir", false);  // Upcast implicite

// Les variables sont toutes de type Vehicule, mais le comportement diffère
vehicule1.accelerer();  // "Vitesse actuelle: 5 km/h"
vehicule2.accelerer();  // "La voiture accélère! Vitesse: 10 km/h"
vehicule3.accelerer();  // "La moto accélère rapidement! Vitesse: 15 km/h"

// Même chose pour klaxonner
vehicule1.klaxonner();  // "Beep beep!"
vehicule2.klaxonner();  // "Beep beep!" (hérite sans redéfinir)
vehicule3.klaxonner();  // "Tut tut!" (redéfini)

Démonstration du polymorphisme: chaque forme implémente la méthode "dessiner" différemment.
// Interface commune pour toutes les formes public interface Forme { void dessiner(); double calculerSurface(); } // Implémentations concrètes public class Cercle implements Forme { private double rayon; public Cercle(double rayon) { this.rayon = rayon; } @Override public void dessiner() { System.out.println("Dessin d'un cercle de rayon " + rayon); } @Override public double calculerSurface() { return Math.PI * rayon * rayon; } } public class Rectangle implements Forme { private double longueur; private double largeur; public Rectangle(double longueur, double largeur) { this.longueur = longueur; this.largeur = largeur; } @Override public void dessiner() { System.out.println("Dessin d'un rectangle de dimensions " + longueur + "x" + largeur); } @Override public double calculerSurface() { return longueur * largeur; } } public class Triangle implements Forme { private double base; private double hauteur; public Triangle(double base, double hauteur) { this.base = base; this.hauteur = hauteur; } @Override public void dessiner() { System.out.println("Dessin d'un triangle de base " + base + " et de hauteur " + hauteur); } @Override public double calculerSurface() { return (base * hauteur) / 2; } } // Utilisation polymorphique public class TestForme { public static void main(String[] args) { // Tableau de formes de différents types Forme[] formes = new Forme[3]; formes[0] = new Cercle(5); formes[1] = new Rectangle(4, 6); formes[2] = new Triangle(3, 4); // Appel polymorphique des méthodes for (Forme forme : formes) { forme.dessiner(); System.out.println("Surface: " + forme.calculerSurface()); } } }

Avantages du polymorphisme

  • Flexibilité - Le même code peut traiter différents types d'objets
  • Extensibilité - Facile d'ajouter de nouveaux types sans modifier le code existant
  • Simplification - Permet de traiter des objets différents de manière uniforme

Concept clé: Avec le polymorphisme, vous pouvez programmer en fonction d'une interface plutôt que d'une implémentation spécifique. C'est une application du principe de conception "Program to an interface, not an implementation".
